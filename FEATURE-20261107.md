# PM-Plan feature build 2026-11-07

Base: 10-30 source + IP ban (pm-plan-ipban) + captcha / model square / ZCode contribute / static serving, all restored from the production binary (pm-plan-prod, sha256 6d7384c3…) by black-box comparison.

## Restored from the prod binary (parity with 8881)
- `src/captcha.rs`: `GET /api/captcha/challenge` → `{CAPTCHA_BASE}/api/captcha/challenge?scene=checkin` (scene is always checkin) with `X-API-Key`. `POST /api/captcha/verify` passes through. `POST /api/checkin {captcha_token}` checks HMAC-SHA256(CAPTCHA_SECRET, python json.dumps(payload, sort_keys=True)), the scene must be checkin, and the token expires after CAPTCHA_TTL from issued_at. Error texts and codes match prod. Missing CAPTCHA_API_KEY or CAPTCHA_SECRET returns 503 captcha_disabled.
  - Only intentional difference: a token's challenge id can be used once (in memory). Prod accepted the same token for different accounts.
- `src/zcode.rs`: `GET /api/v1/zcode/contribute` → `GET http://127.0.0.1:3431/login?type=1` with `Bearer ZCODE_MAGPIE_KEY`. Returns `{id,url}`. Error texts match prod.
- `api.rs`: `/api/model-square` (requires login) and `/api/model-tiers` (public). Output is identical to prod for the same DB.
- `main.rs`: the CSP allows Cloudflare Insights. `/favicon.ico` returns 307 to `/static/logo.jpg`. The SPA fallback returns index.html with 200, except for paths under `/static/` or ending in a file extension, which return 404.
- `ipban.rs`: the list key is `ip_bans`, the unban message is 「该地址不在封禁列表中」, the audit action is `ip.release`, and the account cascade skips only root. These match prod. Manual ban (POST) stays as an addition.
- `web/`: taken from the prod web dir, plus the new admin UI.

## New
- Migration `0003_channel_test_headers.sql`, additive only. On `channels` it adds extra_headers jsonb, strip_reasoning_with_tools bool, param_override jsonb, test_model, test_endpoint, and last_test_at/ok/ms/model. On `channel_models` it adds last_test_at/ok/ms/error.
- Channel model test: `POST /api/admin/channels/{id}/test {"model": "..."}` (an empty body keeps the old /models connectivity check), and `POST /api/admin/channels/test-all`. Settings `channel_auto_test_minutes` (0 = off) and `channel_auto_disable` (default off).
- Per-channel extra headers, param override, and stripping reasoning params when tools are present (`src/channel_opts.rs`). These apply to proxying and to tests.
- Quota 429 errors: message and type are the Chinese text, and code stays quota_5h, quota_7d or quota_30d.

## Deploy (replace prod)
```
sudo -u postgres pg_dump -Fc pmplan > /data/pm-plan-prod/backups/pmplan-before-feature-$(date +%Y%m%d%H%M).dump
cp -a /data/pm-plan-prod/bin/pm-plan /data/pm-plan-prod/backups/pm-plan.6d7384c3
tar czf /data/pm-plan-prod/backups/web-before-feature.tgz -C /data/pm-plan-prod web
sudo systemctl stop pm-plan-prod
install -m 755 /data/pm-plan-feature/bin/pm-plan /data/pm-plan-prod/bin/pm-plan
rm -rf /data/pm-plan-prod/web && cp -a /data/pm-plan-feature/web /data/pm-plan-prod/web
sudo systemctl start pm-plan-prod     # runs migration 0003 automatically
curl -s 127.0.0.1:8881/api/health
```
The .env needs no changes. Optional: IP_FLOOD_PER_SEC and IP_GUARD_ALLOW (defaults 30 and empty).

## Rollback
```
sudo systemctl stop pm-plan-prod
cp -a /data/pm-plan-prod/backups/pm-plan.6d7384c3 /data/pm-plan-prod/bin/pm-plan
rm -rf /data/pm-plan-prod/web && tar xzf /data/pm-plan-prod/backups/web-before-feature.tgz -C /data/pm-plan-prod
sudo -u postgres psql -d pmplan -c "DELETE FROM _sqlx_migrations WHERE version = 3"   # required, see below
sudo systemctl start pm-plan-prod
```
The old binary refuses to start while version 3 is recorded ("migration 3 was previously applied but is missing"). The new columns can stay, because the old binary ignores them. If the new version is deployed again later, 0003 re-applies cleanly (ADD COLUMN IF NOT EXISTS). This was rehearsed on pmplan_featuretest.
